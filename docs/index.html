EC2 Nitro Sandbox Workshop（2026-11-17 实测），仓库 github.com/sunchaoqun/nitro-sandbox

EC2 Nitro Sandbox 实测：只有镜像没被改过的 Sandbox 才拿得到 KMS 里的密钥；instance store 读得和直测一样快，写入速度取决于机型

在一台 i7i.2xlarge 上从零搭起来，测三件事：KMS 能不能只对 PCR 匹配的 Sandbox 放行；以太坊交易怎么签、谁能签； 把整块 instance store 交给 Sandbox 之后读写有多快。下面 28 步照着做大约一个半小时，能得到和这里一样的结果。每一步执行的都是仓库里的脚本。

更正（2026-11-17）：早先版本只给了 i7i.2xlarge 的写入数字（直测的 25%），并把原因说成 Sandbox 本身的限制，这不准确。 重新实测的结论是：Sandbox 的写入要经过 parent 内核的缓存回写，速度主要取决于机型。i7i.2xlarge 上 parent 自己带缓存写也只有约 424 MB/s； i7i.8xlarge 上单盘 Sandbox 能写约 1,876～2,042 MB/s，两块盘在 Sandbox 里组 RAID 0 能写约 4,068 MB/s。大机型上还要把 parent 的 dirty 门槛改成固定值，setup.sh 已经做了。详见 A 的结果。

测的是什么

所有测试都在同一台 parent 上做。Sandbox 是 parent 上用 Firecracker 起的 microVM，Nitro 把它的内存和 parent 隔开，并通过 /dev/nsm 给出签过名的 attestation 文档。

机器
i7i.2xlarge（8 vCPU，64 GiB），1 块 1875 GB NVMe instance store，us-west-1 按需价 $0.83/小时；实例角色 nitro-sandbox-workshop
系统
Amazon Linux 2023，kernel 6.18.62，Firecracker v1.18.0，内存池 48 GiB
Sandbox
confidential 模式（非 debug），4 个独占 vCPU，4 GiB 内存；内核用 parent 的 /boot/vmlinuz，initrd 由 dracut 生成，rootfs 是 Ubuntu 24.04
parent 设置
dirty 门槛固定为 2 GiB / 512 MiB（vm.dirty_bytes / vm.dirty_background_bytes，setup.sh 写进 /etc/sysctl.d/）
A 部分
fio direct=1：大文件写入、大块顺序写、顺序读、4K 随机读、4K 随机写、QD1 读延迟，parent 直测和 Sandbox 各跑一遍
B 部分
KMS key 只认这台 Sandbox 的 PCR0：带 attestation 解密和 ETH 钱包；不带 attestation、parent、封口、改镜像、debug 模式都必须被拒；外加 KMS Sign 签 ETH 交易和 Sepolia 真转一笔
机器分工
标着"工作机"的步骤在你自己的电脑上做（装好 AWS CLI v2、git、python3），其余都在 parent 上做；两边都要 clone 这个仓库。Sandbox 里不用手动操作，脚本会自己 ssh 进去

    创建实例角色和 ETH 签名 key 在 工作机 上

    ETH key 是 KMS 里的 secp256k1 密钥，私钥不出 KMS。实例角色只能对它做 Sign/GetPublicKey，外加 GenerateRandom（NSM 探针用）。已经有了会跳过，可以重复执行。

    bash workstation/prereq.sh
    脚本内容：workstation/prereq.sh（36 行）
    #!/usr/bin/env bash
# 【工作机】实例角色 + ETH 签名 key。已经有了就跳过，可以重复执行。
set -euo pipefail
source "$(dirname "$0")/../config.sh"
ACCT=$(aws sts get-caller-identity --query Account --output text)
echo "账号 $ACCT，区域 $AWS_REGION"

# 1) KMS 里的 secp256k1 签名 key：私钥不出 KMS，用 kms:Sign 签以太坊交易
if aws kms describe-key --key-id "$ETH_KEY_ALIAS" >/dev/null 2>&1; then
  echo "ETH key 已存在：$ETH_KEY_ALIAS"
else
  KEY_ID=$(aws kms create-key --key-spec ECC_SECG_P256K1 --key-usage SIGN_VERIFY \
    --description "nitro sandbox workshop: eth signer" --query KeyMetadata.KeyId --output text)
  aws kms create-alias --alias-name "$ETH_KEY_ALIAS" --target-key-id "$KEY_ID"
  echo "ETH key 已创建：$ETH_KEY_ALIAS（$KEY_ID）"
fi
ETH_KEY_ARN=$(aws kms describe-key --key-id "$ETH_KEY_ALIAS" --query KeyMetadata.Arn --output text)

# 2) 实例角色：只能对这把 ETH key 做 Sign/GetPublicKey，外加 GenerateRandom（NSM 探针用）
if aws iam get-role --role-name "$ROLE_NAME" >/dev/null 2>&1; then
  echo "角色已存在：$ROLE_NAME"
else
  aws iam create-role --role-name "$ROLE_NAME" --query Role.Arn --output text --assume-role-policy-document \
    '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ec2.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
fi
aws iam put-role-policy --role-name "$ROLE_NAME" --policy-name kms-eth-sign --policy-document \
  "{\"Version\":\"2012-10-17\",\"Statement\":[{\"Effect\":\"Allow\",\"Action\":[\"kms:Sign\",\"kms:GetPublicKey\"],\"Resource\":\"$ETH_KEY_ARN\"}]}"
aws iam put-role-policy --role-name "$ROLE_NAME" --policy-name kms-generate-random --policy-document \
  '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"kms:GenerateRandom","Resource":"*"}]}'
if ! aws iam get-instance-profile --instance-profile-name "$ROLE_NAME" >/dev/null 2>&1; then
  aws iam create-instance-profile --instance-profile-name "$ROLE_NAME" >/dev/null
  aws iam add-role-to-instance-profile --instance-profile-name "$ROLE_NAME" --role-name "$ROLE_NAME"
  echo "instance profile 已创建，等 15 秒让它生效"; sleep 15
fi
echo "角色策略：$(aws iam list-role-policies --role-name "$ROLE_NAME" --query 'PolicyNames' --output text)"
echo "完成"

    装 fio 和 Firecracker，预留内存池（会重启） 在 parent 上

    Sandbox 的内存来自驱动预留的连续内存池，不预留就起不来。脚本还会把 dirty 门槛改成固定值（vm.dirty_bytes=2G / vm.dirty_background_bytes=512M），大机型上不改的话 Sandbox 写入只有约 500 MB/s（见常见问题）。最后会重启 parent，1 分钟后重新登录，并 cd ~/nitro-sandbox。

    bash parent/setup.sh
    脚本内容：parent/setup.sh（23 行）
    #!/usr/bin/env bash
# 【parent】确认驱动支持 Sandbox，装 fio 和 Firecracker，预留内存池，然后重启
set -euo pipefail
source "$(dirname "$0")/../config.sh"
uname -r                                  # 要 ≥ 6.18.51-120.162.amzn2023
ls /sys/class/misc/nitro_enclaves/        # 必须有 cpu_pool  mem_pool  pcie_slots

sudo dnf install -y -q fio squashfs-tools iptables-nft
ARCH=$(uname -m); TMP=$(mktemp -d)
curl -fsSL https://github.com/firecracker-microvm/firecracker/releases/download/$FC_VERSION/firecracker-$FC_VERSION-$ARCH.tgz | tar -xz -C "$TMP"
sudo install -m 0755 "$TMP/release-$FC_VERSION-$ARCH/firecracker-$FC_VERSION-$ARCH" /usr/local/bin/firecracker
firecracker --version | head -1           # Firecracker v1.18.0

# 内存池：不预留的话 Firecracker 报 "No space left on device (os error 28)"。
# 留得大一点是故意的：page cache 不会用内存池，parent 只剩 ~13 GB 能缓存，读测试不会被缓存抬高
# dirty 门槛改成固定值（重要）：默认按比例算，会把内存池（CMA）的空闲内存也算进去，但块设备的 page cache 用不了内存池。
# 不改的话，大量写入时 dirty 页会占满内存池以外的内存，Sandbox 的写入掉到 ~400 MB/s，多线程写甚至会把 parent 卡死。
printf 'vm.dirty_bytes = 2147483648\nvm.dirty_background_bytes = 536870912\n' | sudo tee /etc/sysctl.d/90-nitro-sandbox.conf >/dev/null
sudo sysctl -q -p /etc/sysctl.d/90-nitro-sandbox.conf
sudo grubby --update-kernel=ALL --remove-args="nitro_enclaves.mempool"
sudo grubby --update-kernel=ALL --args="nitro_enclaves.mempool=$MEMPOOL"
echo "即将重启，1 分钟后重新登录"
sudo systemctl reboot

    确认内存池，记下 instance store 的稳定路径 在 parent 上

    NVMe 的编号每次开机都可能变：实测重启后 nvme1n1 一次是 instance store，一次是 EBS 根盘。所以后面一律用按序列号的 /dev/disk/by-id 路径，脚本会确认型号是 Instance Storage。

    cd ~/nitro-sandbox
bash parent/after-reboot.sh
    脚本内容：parent/after-reboot.sh（15 行）
    #!/usr/bin/env bash
# 【parent】重启后：确认内存池，找到 instance store 的稳定路径
set -euo pipefail
source "$(dirname "$0")/../config.sh"
grep -o 'nitro_enclaves.mempool=[^ ]*' /proc/cmdline
echo "mem_pool: $(( $(cat /sys/class/misc/nitro_enclaves/mem_pool/total) / 1048576 )) MiB"
echo "pcie_slots: $(cat /sys/class/misc/nitro_enclaves/pcie_slots)"   # ≥ 4
sysctl vm.dirty_bytes vm.dirty_background_bytes                       # 2147483648 / 536870912
lsblk -d -o NAME,SIZE,MODEL

# NVMe 的编号重启后会变（实测：nvme1n1 一次是 instance store，一次是 EBS 根盘），一律用 by-id 路径
mkdir -p "$WORK"
ISD=/dev/disk/by-id/$(ls /dev/disk/by-id/ | grep -E '^nvme-Amazon_EC2_NVMe_Instance_Storage_[A-Za-z0-9]+$' | head -1)
lsblk -dno MODEL "$(readlink -f "$ISD")" | grep -q "Instance Storage" || { echo "没找到 instance store"; exit 1; }
echo "ISD=$ISD" | tee "$WORK/env"

    准备 Sandbox 的内核、initrd 和 rootfs 在 parent 上

    内核直接用 parent 自己的 /boot/vmlinuz，dracut 打一个带 virtio 和 nsm 驱动的 initrd；rootfs 是 Firecracker CI 的 Ubuntu 24.04，chroot 进去装好 fio。大约 30 秒，debconf 的提示可以忽略。

    bash parent/build-guest.sh
    脚本内容：parent/build-guest.sh（30 行）
    #!/usr/bin/env bash
# 【parent】准备 Sandbox：内核用 parent 自己的，initrd 用 dracut 生成，rootfs 用 Firecracker CI 的 Ubuntu 24.04 + fio
set -euo pipefail
source "$(dirname "$0")/../config.sh"
cd "$WORK"
K=$(uname -r)
sudo dracut --force --no-hostonly --add-drivers "virtio_pci virtio_blk virtio_net nsm" initrd.img "$K" 2>/dev/null
sudo ls -la initrd.img

S3=https://s3.amazonaws.com/spec.ccfc.min
P=$(curl -fsSL "$S3?list-type=2&prefix=firecracker-ci/&delimiter=/" \
    | grep -oP "(?<=<Prefix>)firecracker-ci/[0-9]{8}-[^/]+/(?=</Prefix>)" | sort | tail -1)
curl -fsSL -o ubuntu.squashfs "$S3/${P}x86_64/ubuntu-24.04.squashfs"
sudo rm -rf rootfs && sudo unsquashfs -q -d rootfs ubuntu.squashfs >/dev/null

rm -f id_rsa id_rsa.pub && ssh-keygen -f id_rsa -N "" -q
sudo mkdir -p rootfs/root/.ssh && sudo cp id_rsa.pub rootfs/root/.ssh/authorized_keys
# CI 镜像精简掉了 apt 要用的目录；resolv.conf 是空的
sudo mkdir -p rootfs/var/tmp rootfs/var/log/apt rootfs/var/cache/apt/archives/partial \
  rootfs/var/lib/apt/lists/partial rootfs/var/cache/debconf rootfs/var/lib/dpkg/updates
sudo chmod 1777 rootfs/tmp rootfs/var/tmp
echo "nameserver 169.254.169.253" | sudo tee rootfs/etc/resolv.conf >/dev/null

for d in proc sys dev dev/pts; do sudo mount --bind /$d rootfs/$d; done
sudo chroot rootfs /usr/bin/env LC_ALL=C DEBIAN_FRONTEND=noninteractive /bin/bash -c \
  'apt-get update -qq && apt-get install -y -qq --no-install-recommends fio >/dev/null && fio --version; apt-get clean'
for d in dev/pts dev sys proc; do sudo umount rootfs/$d; done

为什么 i7i.2xlarge 上写入只有约 425 MB/s

瓶颈在 parent 内核的缓存回写，不在 Sandbox：Sandbox 关掉、parent 自己用带缓存的方式写同一块盘，速度也一样。CPU 很闲，dirty 门槛和写回限流（blk-wbt）都不影响。实测回写时同时在路上的数据只有 1～2 MB，盘的并发几乎没用上（O_DIRECT 队列深度 32 时同一块盘能写 1.7 GB/s）。

怎么看

  • 读几乎不受影响。i7i.2xlarge 上顺序读是直测的 100%，4K 随机读是 80%。代价在延迟：每次读多 22 µs（经过 virtio、DMB 和 Firecracker 用户态），p99 从 84 µs 变成 115 µs。每个 Sandbox 的 4K 随机读大约在 24～34 万 IOPS，大机型上加盘、加 vCPU 也突破不了。
  • 大块写和大文件写取决于 parent 的缓存回写。i7i.2xlarge 上约 425 MB/s（直测的 25%）；i7i.8xlarge 上单盘约 1,876～2,042 MB/s，两块盘在 Sandbox 里 RAID 0 约 4,068 MB/s。要写得快就选大机型、多块盘。
  • 4K 随机写和直测差不多（103%，含最后的 fsync）：Sandbox 的写先进 parent 的 page cache，内核回写时会把相邻的 4K 合并，抵消了一部分开销。
  • parent 能读到 Sandbox 写进盘的明文（数据路径经过 parent）。需要保密就在 Sandbox 里用 dm-crypt 加密，i7i.2xlarge 上实测对读写速度几乎没有影响；要防篡改可以再加 dm-integrity，它会明显降低写入速度，本手册没有测。

    #!/usr/bin/env python3
"""Nitro Sandbox 里的 attestation 工具：向 /dev/nsm 要 attestation 文档、解析 PCR、
解开 KMS 用 Recipient 返回的 CiphertextForRecipient（CMS EnvelopedData）。

直接运行就是可行性探针：拿 attestation 文档 → 打印 PCR → 调 KMS GenerateRandom(Recipient)
→ 在本地解开结果。能跑通说明 NSM 可用，而且 KMS 接受这台 Sandbox 的 attestation 文档。
"""
import argparse
import ctypes
import fcntl
import os

import cbor2
from asn1crypto import cms
from cryptography.hazmat.primitives import hashes, padding, serialization
from cryptography.hazmat.primitives.asymmetric import padding as asym_padding
from cryptography.hazmat.primitives.asymmetric import rsa
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes

# include/uapi/linux/nsm.h：_IOWR(0x0A, 0, struct nsm_raw)，struct nsm_raw 是两个 {u64 addr; u64 len}
NSM_IOCTL_RAW = (3 << 30) | (32 << 16) | (0x0A << 8) | 0
NSM_RESPONSE_MAX_SIZE = 0x3000


def nsm_request(request, device="/dev/nsm"):
    req = cbor2.dumps(request)
    req_buf = ctypes.create_string_buffer(req, len(req))
    resp_buf = ctypes.create_string_buffer(NSM_RESPONSE_MAX_SIZE)
    msg = (ctypes.c_uint64 * 4)(ctypes.addressof(req_buf), len(req),
                                ctypes.addressof(resp_buf), NSM_RESPONSE_MAX_SIZE)
    fd = os.open(device, os.O_RDWR)
    try:
        fcntl.ioctl(fd, NSM_IOCTL_RAW, msg, True)
    finally:
        os.close(fd)
    return cbor2.loads(resp_buf.raw[:msg[3]])


def attestation_document(public_key_der=None, user_data=None, nonce=None):
    resp = nsm_request({"Attestation": {"user_data": user_data, "nonce": nonce,
                                        "public_key": public_key_der}})
    if "Attestation" not in resp:
        raise RuntimeError(f"NSM 返回错误: {resp}")
    return resp["Attestation"]["document"]


def describe_pcr(index):
    resp = nsm_request({"DescribePCR": {"index": index}})
    if "DescribePCR" not in resp:
        raise RuntimeError(f"NSM 返回错误: {resp}")
    return resp["DescribePCR"]["data"], resp["DescribePCR"]["lock"]


def extend_pcr(index, data):
    # PCR16～31 可以在运行时扩展：new = SHA384(old || data)，不能撤销，重启才清零
    resp = nsm_request({"ExtendPCR": {"index": index, "data": data}})
    if "ExtendPCR" not in resp:
        raise RuntimeError(f"NSM 返回错误: {resp}")
    return resp["ExtendPCR"]["data"]


def lock_pcr(index):
    # 锁定后不能再扩展；attestation 文档只包含已锁定的 PCR
    resp = nsm_request({"LockPCR": {"index": index}})
    if resp != "LockPCR" and not (isinstance(resp, dict) and "LockPCR" in resp):
        raise RuntimeError(f"NSM 返回错误: {resp}")


def parse_attestation_document(doc):
    # COSE_Sign1：[protected, unprotected, payload, signature]，可能带 CBOR tag 18
    cose = cbor2.loads(doc)
    if isinstance(cose, cbor2.CBORTag):
        cose = cose.value
    return cbor2.loads(cose[2])


def new_recipient_key():
    key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
    pub_der = key.public_key().public_bytes(serialization.Encoding.DER,
                                            serialization.PublicFormat.SubjectPublicKeyInfo)
    return key, pub_der


def cms_decrypt(ciphertext_for_recipient, private_key):
    """解开 KMS 的 CiphertextForRecipient：RSAES-OAEP-SHA256 包着内容密钥，内容用 AES-CBC 加密。"""
    info = cms.ContentInfo.load(ciphertext_for_recipient)
    if info["content_type"].native != "enveloped_data":
        raise ValueError(f"不是 EnvelopedData: {info['content_type'].native}")
    env = info["content"]
    ktri = env["recipient_infos"][0].chosen
    kea = ktri["key_encryption_algorithm"]
    if kea["algorithm"].native != "rsaes_oaep":
        raise ValueError(f"不支持的密钥加密算法: {kea['algorithm'].native}")
    cek = private_key.decrypt(ktri["encrypted_key"].native, asym_padding.OAEP(
        mgf=asym_padding.MGF1(hashes.SHA256()), algorithm=hashes.SHA256(), label=None))
    eci = env["encrypted_content_info"]
    alg = eci["content_encryption_algorithm"]
    if alg["algorithm"].native not in ("aes128_cbc", "aes192_cbc", "aes256_cbc"):
        raise ValueError(f"不支持的内容加密算法: {alg['algorithm'].dotted}")
    dec = Cipher(algorithms.AES(cek), modes.CBC(alg["parameters"].native)).decryptor()
    padded = dec.update(eci["encrypted_content"].native) + dec.finalize()
    unpadder = padding.PKCS7(128).unpadder()
    return unpadder.update(padded) + unpadder.finalize()


def main():
    p = argparse.ArgumentParser()
    p.add_argument("--region", default=os.environ.get("AWS_REGION") or os.environ.get("AWS_DEFAULT_REGION"))
    p.add_argument("--skip-kms", action="store_true", help="只测 NSM，不调 KMS")
    a = p.parse_args()

    key, pub_der = new_recipient_key()
    doc = attestation_document(public_key_der=pub_der)
    payload = parse_attestation_document(doc)
    print(f"attestation 文档: {len(doc)} 字节, module_id={payload.get('module_id')}, digest={payload.get('digest')}")
    for idx in sorted(payload["pcrs"]):
        val = payload["pcrs"][idx]
        if any(val):
            print(f"  PCR{idx:<2} {val.hex()}")
    zero = [i for i, v in payload["pcrs"].items() if not any(v)]
    print(f"  全零的 PCR: {sorted(zero)}（debug_mode 下 0/1/2 全零是正常的）")

    if a.skip_kms:
        return
    import boto3
    if not a.region:
        raise SystemExit("需要 --region 或者环境变量 AWS_REGION")
    kms = boto3.client("kms", region_name=a.region)
    resp = kms.generate_random(NumberOfBytes=32, Recipient={
        "KeyEncryptionAlgorithm": "RSAES_OAEP_SHA_256", "AttestationDocument": doc})
    if resp.get("Plaintext"):
        raise SystemExit("KMS 返回了明文，说明它没有按 attestation 处理")
    rnd = cms_decrypt(resp["CiphertextForRecipient"], key)
    print(f"KMS GenerateRandom(Recipient) OK：在 Sandbox 里解开了 {len(rnd)} 字节 → KMS 接受这份 attestation 文档")


if __name__ == "__main__":
    main()

SECP256K1_N = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141


def kms_public_key(kms, key_id):
    der = kms.get_public_key(KeyId=key_id)["PublicKey"]
    # SubjectPublicKeyInfo 的最后 65 字节是未压缩点 04||X||Y
    point = der[-65:]
    if point[0] != 0x04:
        raise ValueError("不是未压缩的 EC 公钥，确认 KeySpec 是 ECC_SECG_P256K1")
    return keys.PublicKey(point[1:])


def der_to_rs(sig):
    # ECDSA-Sig-Value ::= SEQUENCE { r INTEGER, s INTEGER }，长度 <= 72，都是短格式
    if sig[0] != 0x30 or sig[2] != 0x02:
        raise ValueError("签名不是 DER SEQUENCE")
    r_len = sig[3]
    r = int.from_bytes(sig[4:4 + r_len], "big")
    off = 4 + r_len
    if sig[off] != 0x02:
        raise ValueError("签名里 s 不是 INTEGER")
    s_len = sig[off + 1]
    s = int.from_bytes(sig[off + 2:off + 2 + s_len], "big")
    return r, s


def kms_sign_digest(kms, key_id, digest, pub):
    sig = kms.sign(KeyId=key_id, Message=digest, MessageType="DIGEST",
                   SigningAlgorithm="ECDSA_SHA_256")["Signature"]
    r, s = der_to_rs(sig)
    # EIP-2：以太坊只接受 low-s，KMS 不保证
    if s > SECP256K1_N // 2:
        s = SECP256K1_N - s
    # KMS 不返回 recovery id，两个都试一下，能恢复出同一个公钥的就是 v
    for v in (0, 1):
        if keys.Signature(vrs=(v, r, s)).recover_public_key_from_msg_hash(digest) == pub:
            return v, r, s
    raise RuntimeError("恢复不出 KMS 公钥，签名有问题")


def rpc_call(url, method, params):
    body = json.dumps({"jsonrpc": "2.0", "id": 1, "method": method, "params": params}).encode()
    # 公共节点（如 publicnode）会对 Python-urllib 的默认 UA 返回 403
    req = urllib.request.Request(url, body, {"Content-Type": "application/json",
                                             "User-Agent": "kms-sign-tx/1.0"})
    with urllib.request.urlopen(req, timeout=15) as resp:
        out = json.load(resp)
    if "error" in out:
        raise RuntimeError(f"{method}: {out['error']}")
    return out["result"]


def main():
    p = argparse.ArgumentParser()
    p.add_argument("--key-id", default=os.environ.get("KMS_KEY_ID", "alias/nitro-sandbox-eth"))
    # boto3 只认 AWS_DEFAULT_REGION，不认 AWS_REGION，这里两个都接受
    p.add_argument("--region", default=os.environ.get("AWS_REGION") or os.environ.get("AWS_DEFAULT_REGION"))
    p.add_argument("--to", required=True)
    p.add_argument("--value-wei", type=int, default=0)
    p.add_argument("--data", default="0x")
    p.add_argument("--chain-id", type=int, default=11155111, help="默认 Sepolia")
    p.add_argument("--nonce", type=int, default=0)
    p.add_argument("--gas", type=int, default=21000)
    p.add_argument("--max-fee-wei", type=int, default=30 * 10**9)
    p.add_argument("--priority-fee-wei", type=int, default=1 * 10**9)
    p.add_argument("--rpc", help="以太坊 JSON-RPC，给了就从链上取 nonce/chainId/gas 价格")
    p.add_argument("--send", action="store_true", help="签完广播（需要 --rpc）")
    a = p.parse_args()

    if not a.region:
        raise SystemExit("需要 --region 或者环境变量 AWS_REGION")
    kms = boto3.client("kms", region_name=a.region)
    pub = kms_public_key(kms, a.key_id)
    sender = pub.to_checksum_address()
    print("KMS 地址      :", sender)

    if a.rpc:
        a.chain_id = int(rpc_call(a.rpc, "eth_chainId", []), 16)
        a.nonce = int(rpc_call(a.rpc, "eth_getTransactionCount", [sender, "pending"]), 16)
        a.priority_fee_wei = int(rpc_call(a.rpc, "eth_maxPriorityFeePerGas", []), 16)
        base = int(rpc_call(a.rpc, "eth_getBlockByNumber", ["latest", False])["baseFeePerGas"], 16)
        a.max_fee_wei = 2 * base + a.priority_fee_wei
        # 不能写死 21000：实测 Sepolia 上转给一个从没用过的新地址要 ~20 万 gas，给少了交易会失败（手续费照扣）。
        # 估算后多留 10%，没用完的会退回
        est = int(rpc_call(a.rpc, "eth_estimateGas", [{"from": sender, "to": to_checksum_address(a.to),
                                                       "value": hex(a.value_wei), "data": a.data}]), 16)
        a.gas = est * 11 // 10
        print("gas 上限      :", a.gas, f"（估算 {est}）")

    to = bytes.fromhex(to_checksum_address(a.to)[2:])
    data = bytes.fromhex(a.data[2:] if a.data.startswith("0x") else a.data)
    # EIP-1559: 0x02 || rlp([chainId, nonce, maxPriorityFee, maxFee, gas, to, value, data, accessList])
    fields = [a.chain_id, a.nonce, a.priority_fee_wei, a.max_fee_wei, a.gas, to, a.value_wei, data, []]
    digest = keccak(b"\x02" + rlp.encode(fields))
    print("签名哈希      :", "0x" + digest.hex())

    v, r, s = kms_sign_digest(kms, a.key_id, digest, pub)
    raw = b"\x02" + rlp.encode(fields + [v, r, s])
    raw_hex = "0x" + raw.hex()
    print("交易哈希      :", "0x" + keccak(raw).hex())
    print("原始交易      :", raw_hex)

    # 用 eth-account 独立解码一遍，确认发送方就是 KMS 地址
    recovered = Account.recover_transaction(raw_hex)
    print("eth-account 验证发送方:", recovered, "OK" if recovered == sender else "不一致！")
    if recovered != sender:
        raise SystemExit(1)

    if a.send:
        if not a.rpc:
            raise SystemExit("--send 需要 --rpc")
        print("已广播        :", rpc_call(a.rpc, "eth_sendRawTransaction", [raw_hex]))

怎么看

  • attestation 管的是"启动时是什么镜像"。内核、initrd、cmdline 有一点不同 PCR0 就变；同样的镜像每次启动 PCR0 都一样，所以可以把它写进 key policy。
  • rootfs 不在度量范围内。这个测试镜像的 rootfs 里还有 sshd 和 Python，进到 Sandbox 里的人照样能调 KMS。正式使用要把服务放进 initrd（或者用 dm-verity，把 root hash 写进 cmdline），去掉 SSH，并在启动取完密钥后马上封口。
  • 两种 ETH 方案的边界不同。KMS Sign：私钥永远不出 KMS，但谁有实例角色谁就能签（parent 也能）。attestation 钱包：只有 PCR0 匹配、没封口的 Sandbox 能拿到私钥，parent 拿不到；代价是私钥会出现在 Sandbox 内存里。
  • KMS 分不出 Sandbox 和 parent。两者用同一个实例角色，出口 IP 也一样（都经过 parent 的 NAT）；能区分它们的只有 attestation 文档。

现象原因怎么办
Firecracker 报 No space left on device (os error 28)没预留内存池做第 5 步（会重启）
大机型上 Sandbox 写入只有约 500 MB/s，多线程写甚至让 parent 卡死（SSH 都连不上）内存池很大时，按比例算的 dirty 门槛把内存池的空闲内存也算进去，但块设备的 page cache 用不了内存池，dirty 页占满剩下的内存第 5 步已经把 dirty 改成固定值（vm.dirty_bytes=2G / vm.dirty_background_bytes=512M）
i7i.2xlarge 上 Sandbox 写入只有约 425 MB/sparent 内核缓存回写的上限：parent 自己带缓存写同一块盘也一样，跟 Sandbox 无关要写得快就换大机型（i7i.8xlarge 单盘约 2 GB/s），多块盘在 Sandbox 里组 RAID 0
Sandbox 里 4K 随机读只有 1～4 万 IOPS数据盘没写 io_engine，默认是 Sync，一次只处理一个请求用 parent/start-sandbox.sh 生成的配置（"io_engine": "Async"）
Sandbox 里看到的 vdb 只有 30GNVMe 编号重启后变了，拿到的是 EBS 根盘用 /dev/disk/by-id/…Instance_Storage_…（第 6 步）
读的数字比预期高很多读到了没写过的区域（SSD 不读闪存直接返回），或者 parent 的 page cache 太大bench.sh 第一项就是写满测试区；内存池按 config.sh 留 48G，每项前清 cache
